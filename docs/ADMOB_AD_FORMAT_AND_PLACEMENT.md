# Mute AdMob 광고 형식 및 배치 정책

업데이트: 2026-06-29

## 결론

첫 출시에서는 다음 두 형식만 사용한다.

1. 사용자가 직접 선택하는 보상형 광고
2. 홈·공개 스토리 목록 사이의 인라인 적응형 배너

네이티브 고급형 광고는 불이익이 있는 형식은 아니지만 구현 책임과 정책 위험이 더 크므로 2단계로 미룬다. 초기에는 배너로 노출·수익·이탈률 데이터를 확보한 뒤 네이티브 광고 A/B 테스트를 진행한다.

## 현재 연결 상태

- iOS AdMob 앱 ID: `ca-app-pub-4013454985021474~4784155440`
- iOS 보상형 광고 단위 ID: `ca-app-pub-4013454985021474/1566965165`
- 보상형 SSV 콜백:
  `https://oxanqrmkvyniocxwreia.supabase.co/functions/v1/admob-reward-ssv`
- 출석 체크 광고: 20P, 1시간당 1회
- 추가 광고: 10P, 1시간당 1회
- SSV 서명 검증과 거래 ID 중복 방지는 Supabase에서 처리한다.
- 저장소 기본값은 테스트 광고다. 실광고 전환은
  `EXPO_PUBLIC_ADMOB_USE_TEST_ADS=false`로 명시한다.

## 배너 광고 권장안

형식은 `INLINE_ADAPTIVE_BANNER`를 사용한다. 화면 하단에 계속 붙는 고정 배너보다 목록의 자연스러운 중간 지점에 삽입하는 방식이 뮤트 UX에 적합하다.

### 허용 배치

- 메인 홈 방 목록: 방 카드 6~8개 이후 최대 1개
- 공개 스토리 목록: 스토리 카드 6~8개 이후 최대 1개
- 긴 목록에서 추가 노출이 필요하면 광고 사이에 콘텐츠 8개 이상 유지

### 금지 배치

- 채팅방 메시지 목록과 메시지 입력창 주변
- 하단 내비게이션 바로 위 고정 배너
- 로그인·회원가입·전화번호 인증
- 방 생성·가입 신청·비밀번호 입력
- 스토리 작성·댓글 입력·사진 편집
- 결제·아이템샵·포인트 전송
- 프로필·비밀 쪽지·신고·성인인증
- FAB, 더보기, 전송, 뒤로가기 등 조작 버튼과 인접한 위치

### 동작 기준

- 광고 로딩 전에는 빈 광고 공간을 예약하지 않는다.
- 로딩 실패 시 콘텐츠 간격만 정상 복구하고 오류 팝업을 띄우지 않는다.
- 화면당 동시에 표시되는 배너는 1개를 기본으로 한다.
- 광고 제거 구독자는 배너와 향후 네이티브 광고를 보지 않는다.
- 광고 제거 구독자도 본인이 선택하면 보상형 광고를 시청할 수 있다.
- 개발 및 TestFlight에서는 Google 테스트 광고 ID를 사용한다.

## 네이티브 고급형 검토

네이티브 광고는 앱 콘텐츠와 어울리게 구성할 수 있어 장기적으로 배너보다 UX와 수익성이 좋아질 가능성이 있다. 다만 다음 조건을 모두 만족해야 한다.

- `광고`, `Advertisement` 또는 `Sponsored` 표기를 명확히 표시
- 광고 표기는 최소 15x15px 이상
- SDK가 제공하는 AdChoices 영역을 가리지 않음
- 광고와 일반 방·스토리 카드가 완전히 동일하게 보이지 않도록 구분
- 광고 위에 앱 콘텐츠나 버튼을 겹치지 않음
- CTA를 앱 내 일반 버튼으로 오인하게 만들지 않음
- 스크롤·탭·뒤로가기 등 빈번한 조작 영역과 충분한 간격 유지
- 목록에서 바로 보일 광고만 제한적으로 미리 로드
- 한 시간 이상 캐시하지 않고 화면 이탈 시 네이티브 광고 객체 해제
- 디자인별·게재위치별로 별도의 광고 단위 생성

### 도입 조건

- 배너 광고 운영 데이터가 최소 2주 이상 축적됨
- 비정상 클릭률과 사용자 이탈률을 측정할 수 있음
- 광고 제거 구독 권한이 안정적으로 적용됨
- iOS와 Android 각각 실제 기기 QA 완료

## 정책상 주의사항

- 광고 클릭을 유도하거나 클릭 대가를 제공하면 안 된다.
- 포인트는 광고를 끝까지 시청한 보상이며 광고 내부 링크 클릭과 무관해야 한다.
- 실광고를 개발자나 테스터가 반복 클릭하면 무효 트래픽 및 계정 정지 위험이 있다.
- 광고 소재는 앱 연령 등급과 스토어 정책에 맞아야 한다.
- 개인정보 및 광고 동의 상태가 광고 요청을 허용할 때만 SDK를 초기화한다.
