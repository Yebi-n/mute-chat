# 뮤트(Mute) 제품 기능 명세서

## 1. 문서 개요

- 문서 목적: 반익명 커뮤니티 앱 `뮤트(Mute)`의 제품 범위, 정책, 기능 요구사항과 출시 수용 기준을 정의한다.
- 제품명: 뮤트(Mute)
- 한 줄 설명: 관심사와 지역을 중심으로 모이고, 방마다 다른 프로필로 안전하게 대화하는 반익명 커뮤니티.
- 지원 플랫폼: Android, iOS
- 핵심 제약:
  - 국내 휴대폰 본인확인을 통과한 사용자만 계정을 생성할 수 있다.
  - 외부에는 실명 대신 방별 프로필을 노출한다.
  - 앱은 가볍고 빠르게 동작해야 하며 이미지와 실시간 통신 비용을 통제한다.
  - 광고 시청과 인앱 결제로 포인트를 획득하고 꾸미기 기능 등에 사용한다.

## 2. 제품 원칙

1. 반익명성: 서비스 운영자는 제재에 필요한 계정 식별 정보를 보유하되, 멤버 간에는 방별 프로필만 공개한다.
2. 방 중심성: 사용자의 이름, 소개, 프로필 사진과 활동 맥락은 채팅방마다 독립적이다.
3. 승인 기반 참여: 공개 검색이 가능한 방도 가입 승인을 거쳐야 대화할 수 있다.
4. 최소 권한: 운영 권한은 기능별로 분리하고, 권한이 없는 운영자는 해당 기능을 실행할 수 없다.
5. 안전 우선: 신고, 차단, 제재, 성인인증과 운영 감사 기록을 초기 설계에 포함한다.
6. 비용 효율: 이미지 최적화, 페이지네이션, 캐시, 보존 기간 정책으로 서버 비용을 제한한다.
7. 절제된 수익화: 대화 참여 자체는 무료이며, 결제 여부가 운영 권한이나 안전 기능에 영향을 주지 않는다.
8. 비랜덤 커뮤니티: 무작위 상대 연결이 아니라 검색, 방 설명, 가입 승인에 기반한다.
9. 성인 영역 제한: 성인 탭은 음란물·만남 주선 영역이 아니며 노골적 성적 콘텐츠를 금지한다.

## 3. 주요 용어

- 계정 프로필: 인증 전화번호에 연결된 비공개 계정 정보. 타 사용자에게 직접 노출하지 않는다.
- 방별 프로필: 특정 방에서만 사용하는 이름, 소개, 프로필 사진.
- 방장: 방 생성자 또는 방장 권한을 양도받은 단일 사용자.
- 운영자: 방장에게 일부 운영 권한을 부여받은 멤버.
- 스토리: 채팅방에 귀속되는 게시판형 콘텐츠.
- 프로모션: 방장이 실행하여 프로모션 목록에 추가 노출하는 무료 홍보 기능.
- 활성화 노출: 최근 유효 대화 활동에 따라 자동으로 목록 순위가 올라가는 기능.
- 포인트: 광고, 결제 또는 멤버 간 전송으로 획득하고 앱 내 디지털 기능에 사용하는 재화.
- 강퇴: 정해진 기간 동안 해당 방에 입장하거나 재가입 신청하지 못하게 하는 제재.
- 채팅 금지: 정해진 기간 동안 해당 방에 메시지를 보낼 수 없게 하는 제재.

## 4. 사용자 역할

| 역할 | 설명 |
|---|---|
| 방문자 | 앱을 설치했지만 로그인하지 않은 사용자 |
| 일반 사용자 | 국내 휴대폰 본인확인 후 계정을 생성한 사용자 |
| 신청자 | 특정 방에 가입 신청을 제출한 사용자 |
| 멤버 | 가입 승인을 받아 특정 방에 참여 중인 사용자 |
| 운영자 | 방장에게 하나 이상의 세부 권한을 부여받은 멤버 |
| 방장 | 방의 최종 관리 책임자 |
| 서비스 운영자 | 신고 심사, 계정 제재, 법적 요청 대응을 수행하는 내부 관리자 |

- 알림 전체 및 방별 ON/OFF
- 방 편집, 삭제, 방장 양도

## 6. 핵심 사용자 플로우

### 6.1 최초 가입

1. 사용자가 앱을 실행하면 짧은 스플래시를 본다.
2. 서비스 이용약관, 개인정보처리방침, 커뮤니티 운영정책에 동의한다.
3. 휴대전화 번호를 입력하고 국내 본인확인 제공자의 인증 절차를 완료한다.
4. 인증 성공 시 계정을 생성하고 메인 화면으로 이동한다.
5. 인증 실패, 만료, 요청 제한 상태에서는 원인과 재시도 가능 시점을 표시한다.

정책:

- 계정 식별자는 전화번호 원문이 아닌 내부 사용자 ID를 사용한다.
- 전화번호는 암호화 저장하며 검색용 값이 필요하면 별도 키 기반 해시를 사용한다.
- 동일 CI 해시는 하나의 활성 계정에만 연결한다.
- 본인확인 원본 정보는 저장하지 않고 CI는 서버 HMAC 값으로만 저장한다.
- 성인 탭은 서버에서 만 19세 이상 결과가 확인된 계정만 접근한다.

### 6.2 방 탐색과 가입

1. 사용자는 프로모션, Member, 지역별, 성인 탭에서 방 목록을 확인하거나 검색한다.
2. 방 카드를 선택하면 방 설명 화면으로 이동한다.
3. 기존 멤버라면 `채팅으로 이동`, 비멤버라면 `가입 신청`을 표시한다.
4. 비멤버는 신청 전에 방별 이름, 소개, 프로필 사진을 설정한다.
5. 가입 신청이 제출되면 중복 신청을 막고 신청 상태를 표시한다.
6. 방장 또는 가입 승인 권한이 있는 운영자가 승인하거나 거절한다.
7. 승인 시 멤버가 되고 알림을 받으며 채팅방에 진입할 수 있다.

### 6.3 채팅

1. 채팅방 진입 시 최신 메시지 묶음을 먼저 표시한다.
2. 사용자가 텍스트 또는 이미지를 전송한다.
3. 메시지는 서버 승인 후 확정 상태가 되며 실패 시 재전송할 수 있다.
4. 내 메시지와 타인 메시지는 정렬, 프로필, 색상으로 구분한다.
5. 프로필 사진 또는 이름을 누르면 해당 방의 프로필 상세가 열린다.
6. 채팅 금지 중에는 입력창을 비활성화하고 종료 시각을 표시한다.
7. 강퇴 중에는 방 입장과 재신청을 차단하고 종료 시각을 표시한다.

### 6.4 방 생성과 운영

1. 사용자가 방 이름, 설명, 대표 이미지, 해시태그, 카테고리, 지역, 최대 멤버 수, 성인 여부를 입력한다.
2. 금칙어와 필수 입력 검증 후 방을 생성한다.
3. 생성자는 자동으로 방장이 되며 방별 프로필을 설정한다.
4. 방장은 신청을 승인하고 운영자에게 세부 권한을 부여한다.
5. 방장은 프로모션을 실행하거나 방 정보를 편집하고 다른 멤버에게 방장을 양도할 수 있다.
6. 방 삭제 시 확인 문구를 거치고 복구 유예 기간 후 영구 삭제한다.

### 6.5 신고

1. 사용자는 멤버 프로필 또는 방 메뉴에서 신고를 시작한다.
2. 신고 대상, 사유, 상세 설명을 선택하고 제출한다.
3. 서비스는 신고 시점의 대상 정보와 관련 콘텐츠 식별자를 보존한다.
4. 사용자는 접수 완료와 신고 번호를 확인한다.
5. 긴급 위험 사유는 높은 우선순위로 운영 검토 큐에 들어간다.
6. 신고자 정보는 피신고자와 방 운영자에게 공개하지 않는다.

### 6.6 포인트 획득과 전송

1. 사용자는 포인트 화면에서 잔액과 이력을 확인한다.
2. 리워드 광고를 끝까지 시청하면 서버 검증 후 포인트가 적립된다.
3. 멤버 프로필에서 전송 금액과 수신자를 재확인한 뒤 포인트를 보낸다.
4. 전송은 원자적으로 처리하며 성공 후 취소할 수 없음을 명시한다.
5. 이상 거래 탐지를 위해 일/회당 한도와 계정 상태별 제한을 적용한다.

## 8. 기능 요구사항

### 8.1 인증과 계정

- `AUTH-001` 전화번호 본인인증 성공 전에는 계정을 생성할 수 없다.
- `AUTH-002` 인증 요청에는 재전송 대기시간, 일일 시도 제한, 기기 및 IP 기반 속도 제한을 적용한다.
- `AUTH-003` 인증 완료 후 발급한 세션은 안전한 OS 저장소에 보관한다.
- `AUTH-004` 로그아웃 시 현재 기기의 세션과 푸시 토큰 연결을 해제한다.
- `AUTH-005` 설정에서 마스킹된 인증 전화번호를 확인할 수 있다.
- `AUTH-006` 비밀번호를 사용하지 않으며 재로그인은 전화번호 본인인증으로 처리한다.
- `AUTH-007` 탈퇴 시 유예 기간과 법정 보존 항목을 안내하고, 유예 종료 후 개인정보를 삭제 또는 비식별화한다.

### 8.2 방 생성 및 정보

- `ROOM-001` 방 이름, 설명, 대표 이미지, 해시태그, 카테고리, 지역, 최대 멤버 수, 성인 여부를 저장한다.
- `ROOM-002` 방 이름은 2~30자, 설명은 0~500자, 해시태그는 최대 10개로 제한한다.
- `ROOM-003` 최대 멤버 수는 서비스 설정 범위 내에서만 선택할 수 있다.
- `ROOM-004` 방 이름과 해시태그에는 금칙어 및 반복 문자 검사를 적용한다.
- `ROOM-005` 방 삭제는 방장만 가능하고, 확인 문구 입력 후 삭제 대기 상태로 전환한다.
- `ROOM-006` 방장 양도는 현재 활성 멤버에게만 가능하며 양 당사자에게 결과를 알린다.
- `ROOM-007` 방장이 탈퇴하려면 방장 양도 또는 방 삭제를 먼저 완료해야 한다.

### 8.3 방별 프로필과 멤버

- `MEMBER-001` 사용자는 방마다 서로 다른 이름, 소개, 프로필 사진을 설정할 수 있다.
- `MEMBER-002` 이름은 1~20자, 소개는 0~100자로 제한한다.
- `MEMBER-003` 같은 방 내 이름 중복은 허용하되 프로필 상세에서 구분 가능한 짧은 멤버 코드를 표시한다.
- `MEMBER-004` 방별 프로필 변경은 기존 메시지에도 최신 프로필을 표시하되 운영 감사 기록에는 변경 이력을 남긴다.
- `MEMBER-005` 멤버 목록에는 이름, 소개, 프로필 사진과 방장/운영자 배지를 표시한다.
- `MEMBER-006` 가입 신청은 방당 사용자 1건만 활성 상태로 유지한다.

### 8.4 가입 승인

- `JOIN-001` 방장과 가입 승인 권한 보유자는 대기 신청 목록을 볼 수 있다.
- `JOIN-002` 승인 시 최대 멤버 수를 원자적으로 재검증한다.
- `JOIN-003` 거절 시 신청자는 다시 신청할 수 있으나 반복 요청 제한을 적용한다.
- `JOIN-004` 강퇴 제재 중인 사용자는 제재 종료 전 가입을 신청할 수 없다.
- `JOIN-005` 승인/거절 행위는 행위자, 시각, 대상과 함께 감사 기록에 남긴다.

### 8.5 채팅

- `CHAT-001` MVP는 UTF-8 텍스트와 단일 이미지 메시지를 지원한다.
- `CHAT-002` 메시지 길이는 최대 2,000자로 제한한다.
- `CHAT-003` 서버가 생성한 메시지 ID와 시각을 정렬 기준으로 사용한다.
- `CHAT-004` 메시지 목록은 커서 페이지네이션하며 최초 진입 시 최신 30개를 불러온다.
- `CHAT-005` 동일 클라이언트 요청 ID의 중복 메시지는 한 번만 저장한다.
- `CHAT-006` 전송 중, 성공, 실패 상태를 시각적으로 구분하고 실패 메시지는 재전송할 수 있다.
- `CHAT-007` 운영 제재, 가입/퇴장, 방장 양도는 시스템 메시지로 표시한다.
- `CHAT-008` 전체 알림 OFF 또는 방 알림 OFF 상태에서는 해당 푸시를 발송하지 않는다.
- `CHAT-009` 차단한 사용자의 메시지는 기본 접힘 처리하고 사용자가 선택해 볼 수 있게 한다.

### 8.6 이미지

- `IMAGE-001` 갤러리와 카메라에서 이미지를 선택할 수 있다.
- `IMAGE-002` 프로필/대표 이미지는 기본 1:1 크롭, 채팅 이미지는 자유 비율 크롭을 제공한다.
- `IMAGE-003` 업로드 전에 긴 변 기준 최대 2,048px로 축소하고 메타데이터를 제거한다.
- `IMAGE-004` 지원 형식은 JPEG, PNG, WebP/HEIC 입력이며 서버 저장 형식은 WebP 또는 JPEG로 정규화한다.
- `IMAGE-005` 원본이 필요하지 않은 이미지 유형은 최적화본만 저장한다.
- `IMAGE-006` 서버는 확장자가 아닌 실제 MIME과 파일 시그니처를 검증한다.
- `IMAGE-007` 썸네일을 별도 생성하고 목록에서는 썸네일만 내려준다.
- `IMAGE-008` 업로드 실패 시 진행률과 재시도 동작을 제공한다.

### 8.7 검색, 프로모션 및 활성도

- `DISC-001` 방 이름, 방 설명, 해시태그를 통합 검색한다.
- `DISC-002` 검색 결과에 카테고리, 지역, 가입 가능 여부 필터를 제공한다.
- `DISC-003` 이미 가입한 방은 설명 화면의 기본 행동을 `채팅으로 이동`으로 표시한다.
- `DISC-004` 무료 프로모션은 방별 24시간에 1회 실행할 수 있고 2시간 동안 프로모션 점수를 부여한다.
- `DISC-005` 프로모션 실행 시각과 종료 시각을 방장에게 표시한다.
- `DISC-006` 활성 점수는 최근 60분의 서로 다른 발신자 수와 유효 메시지 수를 사용해 계산한다.
- `DISC-007` 동일 사용자의 연속 메시지는 활성 점수 기여를 제한하고 시스템/삭제 메시지는 제외한다.
- `DISC-008` 권장 MVP 활성 기준은 최근 30분 내 서로 다른 3명 이상이 유효 메시지 10개 이상을 작성한 경우다.
- `DISC-009` 최종 목록 점수는 프로모션, 활성도, 신고/제재 상태, 최신성을 반영하되 점수 산식은 서버 설정으로 조정한다.
- `DISC-010` 신고 누적 또는 검토 중인 방은 자동 노출을 제한할 수 있다.

### 8.8 꾸미기와 테마

- `STYLE-001` 사용자는 허용된 팔레트에서 내 채팅 풍선과 텍스트 색상을 선택할 수 있다.
- `STYLE-002` 색상 조합은 WCAG AA 수준의 명암비를 만족하는 조합만 허용한다.
- `STYLE-003` 기본 팔레트는 무료이며 추가 팔레트/테마는 광고 또는 포인트로 잠금 해제할 수 있다.
- `STYLE-004` 상대방의 선택이 가독성을 해칠 경우 로컬 접근성 설정이 우선한다.

### 8.9 알림과 설정

- `SET-001` 전체 푸시 알림 ON/OFF를 제공한다.
- `SET-002` 방별 푸시 알림 ON/OFF를 제공한다.
- `SET-003` 설정에 로그아웃, 개인정보처리방침, 이용약관, 인증 전화번호, 전체 알림, 피드백 메일, 탈퇴를 제공한다.
- `SET-004` OS 알림 권한이 꺼져 있으면 앱 설정 상태와 구분해 OS 설정 이동을 안내한다.

### 8.10 포인트와 수익화

- `POINT-001` 포인트 잔액은 서버 원장 합계로 산출하며 클라이언트 값을 신뢰하지 않는다.
- `POINT-002` 모든 적립/사용/전송은 변경 불가능한 거래 원장에 기록한다.
- `POINT-003` 리워드 광고 완료는 광고 네트워크의 서버 검증 콜백 성공 후 적립한다.
- `POINT-004` 멤버 간 전송은 송신 차감과 수신 적립을 단일 트랜잭션으로 처리한다.
- `POINT-005` 계정당 일일 광고 적립 횟수, 전송 횟수와 금액 한도를 적용한다.
- `POINT-006` 포인트는 현금으로 환전할 수 없고, 환불 및 소멸 정책을 구매 전에 표시한다.
- `POINT-007` 유료 포인트 판매 도입 시 Apple/Google 인앱 결제 정책을 준수하고 서버 영수증 검증을 적용한다.

### 9.2 방 운영 역할

- 방장은 방마다 1명이다.
- 방장은 여러 멤버를 부방장으로 지정하거나 해제할 수 있다.
- 부방장은 가입 승인, 제재, 이름 변경, 스토리 관리, 방 정보 수정을 수행할 수 있다.
- 방 삭제, 방장 양도, 부방장 지정/해제는 방장만 수행할 수 있다.
- 강퇴와 채팅 금지의 기간 선택지는 기존 정책을 유지한다.

권한 규칙:

- 부방장은 방장이나 다른 부방장을 제재하거나 역할을 변경할 수 없다.
- 부방장은 자신의 역할을 타인에게 재위임할 수 없다.
- 방장만 부방장을 지정/해제하고 방장을 양도할 수 있다.
- 모든 운영 행위는 감사 로그에 기록하며 대상 멤버에게 알린다.
- 방장 양도 시 기존 방장은 일반 멤버가 되며, 기존에 별도 부여된 권한만 유지한다.

## 10. 수익화 정책

### 10.1 MVP

- 리워드 광고: 시청 완료 후 소량의 포인트 적립
- 포인트 사용처: 추가 색상, 일정 기간 테마 잠금 해제
- 멤버 간 포인트 선물: 커뮤니티 상호작용 수단

### 10.2 후속

- 인앱 결제 포인트 패키지
- 테마 번들, 프로필 장식, 채팅 효과
- 광고 제거 구독
- 무료 프로모션과 명확히 구분된 스폰서 노출 상품 검토

### 10.3 금지 원칙

- 신고, 차단, 인증, 기본 알림 등 안전 기능은 유료화하지 않는다.
- 운영 권한, 가입 승인 우선권, 제재 회피 수단을 판매하지 않는다.
- 포인트를 현금 또는 외부 재화로 환전하지 않는다.
- 광고 시청을 채팅 참여의 필수 조건으로 만들지 않는다.

## 11. 신고, 안전 및 개인정보

### 11.1 신고 대상과 사유

- 대상: 방, 멤버, 메시지
- 사유:
  - 괴롭힘/모욕
  - 혐오/차별
  - 성적 콘텐츠
  - 미성년자 위험
  - 자해/자살 위험
  - 폭력/범죄 위협
  - 사칭/개인정보 노출
  - 스팸/광고
  - 불법 거래
  - 기타

### 11.2 신고 처리

- 신고 접수 시 신고자, 대상, 사유, 시각, 관련 콘텐츠 ID와 최소 증거 스냅샷을 저장한다.
- 미성년자 위험, 자해, 구체적 폭력 위협은 긴급 큐로 분류한다.
- 조치는 경고, 콘텐츠 숨김/삭제, 노출 제한, 일시 정지, 영구 정지, 방 폐쇄로 구성한다.
- 피신고자에게 신고자의 신원을 공개하지 않는다.
- 반복 허위 신고는 기능 제한 대상이 될 수 있다.
- 신고 관련 데이터는 개인정보처리방침과 내부 보존 정책에 따라 제한적으로 보관한다.

### 11.3 차단과 제재

- 사용자는 같은 방의 다른 사용자를 차단할 수 있다.
- 차단은 상대에게 알리지 않는다.
- 방 운영 제재와 서비스 계정 제재를 분리한다.
- 강퇴/채팅 금지 종료는 서버 시각을 기준으로 자동 처리한다.
- 앱 삭제, 재로그인, 기기 변경으로 제재를 우회할 수 없어야 한다.

### 11.4 개인정보

- 방 멤버에게 전화번호, 실명, 인증 제공자 응답 원문을 노출하지 않는다.
- 로그와 분석 이벤트에 전화번호 원문을 포함하지 않는다.
- 관리자 접근은 역할 기반으로 제한하고 조회 기록을 남긴다.
- 프로필 이미지와 채팅 이미지는 추측 불가능한 객체 키와 만료 가능한 URL로 제공한다.
- 개인정보처리방침에 수집 목적, 보유 기간, 제3자 제공, 처리 위탁, 삭제 절차를 명시한다.

## 12. 성인인증 및 성인 영역

- 성인 방 접근은 전화번호 본인인증과 별도의 성인 여부 확인 결과가 모두 유효해야 한다.
- 생년월일 원문 대신 `성인 인증 여부`, 제공자, 인증 시각, 만료/철회 상태만 최소 저장하는 방식을 우선한다.
- 성인 미인증 사용자는 성인 방의 제목, 이미지, 설명, 검색 결과와 알림을 볼 수 없다.
- 성인 콘텐츠는 기본 탭, 푸시 미리보기, 외부 공유 화면에서 노출하지 않는다.
- 성인 인증이 곧 불법 콘텐츠 허용을 의미하지 않으며 착취물, 비동의 콘텐츠, 미성년자 관련 성적 콘텐츠는 즉시 제재한다.
- 앱스토어 정책과 국내 청소년보호 관련 의무를 출시 전 법률 검토한다.
- 성인 영역은 연령 게이트, 민감 콘텐츠 경고, 신고 진입점을 항상 제공한다.

## 13. 비기능 요구사항

### 13.1 성능

- 콜드 스타트 목표: 중급 기기에서 3초 이내에 조작 가능한 첫 화면 표시.
- 채팅방 최신 메시지 표시 목표: 정상 네트워크에서 P95 1.5초 이내.
- 텍스트 메시지 전송 확정 목표: 정상 네트워크에서 P95 800ms 이내.
- 방 목록은 페이지당 20개를 기본으로 하고 무한 스크롤한다.
- 이미지 목록에서는 원본을 불러오지 않고 화면 크기에 맞는 썸네일을 사용한다.

### 13.2 안정성

- 세션 기준 크래시 없는 비율 99.5% 이상을 MVP 출시 기준으로 한다.
- 메시지 전송은 중복 방지 키를 사용한다.
- 포인트 거래와 가입 승인/정원 검증은 원자적으로 처리한다.
- 네트워크 복구 후 미확정 전송 상태를 재동기화한다.

### 13.3 접근성 및 UI

- 기본 배경은 흰색, 포인트는 녹색 계열, 위험 행동은 핑크/빨강 계열을 사용한다.
- 그림자 기반 뉴모피즘은 장식에 제한하고 입력창, 버튼, 카드 경계는 명확한 대비를 유지한다.
- 프로필 이미지는 원형, 카드와 버튼은 과도하게 각지지 않은 모서리를 사용한다.
- 태그는 Notion 스타일의 간결한 칩으로 표현한다.
- 터치 영역은 최소 44x44pt 상당을 확보한다.
- 색상만으로 상태를 구분하지 않고 텍스트/아이콘을 병행한다.

### 13.4 비용 통제

- 이미지 클라이언트 선압축과 CDN 캐시를 사용한다.
- 메시지/방 목록은 커서 페이지네이션한다.
- 실시간 연결은 활성 채팅방에서만 유지하고 백그라운드에서는 푸시로 전환한다.
- 프로모션/활성 점수는 이벤트마다 전체 재계산하지 않고 시간 버킷 집계 또는 증분 카운터를 사용한다.
- 분석 이벤트는 필수 퍼널과 오류 진단 중심으로 제한한다.
- 개발/스테이징/운영 환경별 저장소 보존 기간과 로그 레벨을 구분한다.

## 15. 수용 기준

### 15.1 인증

- 유효한 본인인증 결과로 신규 계정이 한 번만 생성된다.
- 동일 전화번호로 재인증하면 기존 계정에 로그인된다.
- 인증 실패/만료/요청 제한 상태가 각각 구분되어 표시된다.
- 로그아웃 후 이전 세션으로 보호 API를 호출할 수 없다.

### 15.2 방과 가입

- 필수값과 길이 제한을 만족한 사용자는 방을 생성할 수 있다.
- 비멤버는 채팅에 접근할 수 없고 가입 신청만 제출할 수 있다.
- 승인 권한이 없는 멤버는 신청 목록 조회 및 승인 API를 사용할 수 없다.
- 정원 마지막 한 자리에 동시 승인 요청이 발생해도 한 명만 승인된다.
- 기존 멤버가 방 설명을 열면 한 번의 행동으로 채팅에 진입한다.

### 15.3 권한과 제재

- 각 세부 권한은 독립적으로 부여/회수되며 미보유 기능은 UI와 API 모두 차단된다.
- 강퇴와 채팅 금지는 지정된 모든 기간 옵션으로 설정할 수 있다.
- 제재 기간에는 서버가 입장/전송 요청을 거부하고 종료 후 자동 허용한다.
- 방장 양도 후 새 방장만 권한 부여, 방 삭제, 재양도를 할 수 있다.
- 모든 운영 행위에 행위자, 대상, 종류, 시각이 기록된다.

### 15.4 채팅과 이미지

- 텍스트 메시지가 중복 없이 전송되고 재접속 후 동일 순서로 보인다.
- 전송 실패가 표시되고 사용자가 재전송할 수 있다.
- 카메라/갤러리 이미지가 크롭 및 압축 후 업로드된다.
- 업로드된 이미지의 긴 변, 형식, 용량이 서버 정책을 만족한다.
- 채팅 금지 사용자는 텍스트와 이미지를 모두 전송할 수 없다.

### 15.5 검색과 노출

- 방 제목, 설명, 해시태그 각각의 검색어로 대상 방이 검색된다.
- 프로모션 방과 활성 방의 배지가 서로 다르게 표시된다.
- 동일 방은 24시간 내 무료 프로모션을 중복 실행할 수 없다.
- 단일 사용자의 도배만으로 활성 기준을 충족할 수 없다.
- 성인 미인증 계정의 응답 데이터에 성인 방 정보가 포함되지 않는다.

### 15.6 포인트

- 검증된 광고 완료 콜백 한 건당 한 번만 포인트가 적립된다.
- 잔액 부족 상태에서 포인트 전송은 실패하고 양쪽 잔액이 변하지 않는다.
- 성공한 전송은 송신/수신 원장과 잔액이 일치한다.
- 제한 횟수 또는 금액을 넘으면 명확한 오류와 재시도 가능 시점을 표시한다.

### 15.7 신고와 안전

- 방, 멤버, 메시지를 각각 신고할 수 있다.
- 피신고자에게 신고자 식별 정보가 노출되지 않는다.
- 차단 후 대상 사용자의 메시지가 기본 접힘 처리된다.
- 긴급 사유 신고는 일반 신고보다 높은 우선순위로 분류된다.
- 탈퇴/삭제 이후에도 법적 또는 안전상 필요한 신고 증거만 정책 기간 동안 보존된다.

### 15.8 출시 품질 게이트

- Android/iOS 핵심 플로우 E2E 테스트가 모두 통과한다.
- 심각도 Critical/High 보안 취약점이 0건이다.
- 결제 도입 시 스토어 샌드박스 구매, 복원, 실패, 중복 콜백 테스트가 통과한다.
- 개인정보처리방침, 이용약관, 커뮤니티 가이드라인, 신고 처리 정책이 앱에서 접근 가능하다.
- 크래시 없는 세션 99.5% 이상, 주요 API P95 목표를 베타 기간에 충족한다.

## 16. 결정이 필요한 항목

- 국내 본인인증/성인인증 제공자와 건당 비용
- MVP 최대 방 인원과 사용자당 방 생성/가입 한도
- 메시지 및 이미지 기본 보존 기간
- 무료 프로모션 주기와 활성 점수 가중치
- 포인트 초기 단가, 광고 보상량, 전송 한도
- Member 탭의 정확한 분류 정책과 금지 콘텐츠 범위
- 서비스 운영 인력의 신고 대응 시간과 긴급 대응 절차
- 성인 영역 제공이 앱스토어 심사 및 사업 정책상 가능한지에 대한 사전 검토
