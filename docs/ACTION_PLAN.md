# Mute 실행 계획

## 1. 목표

Android와 iOS에서 동작하는 반익명 채팅 앱의 MVP를 출시한다. 전화번호 인증, 방별 프로필, 승인형 채팅방, 세부 운영 권한, 안전 기능, 저비용 이미지/실시간 구조, 리워드 광고 기반 포인트를 핵심 범위로 한다.

## 2. 성공 지표

### 제품 지표

- 가입 인증 완료율 80% 이상
- 방 상세 조회 대비 가입 신청 전환율 15% 이상
- 가입 승인 후 24시간 내 첫 메시지 작성률 60% 이상
- 신규 가입자의 7일 유지율 20% 이상
- 활성 방의 주간 재방문 멤버 비율 30% 이상
- 신고 접수 후 최초 검토 시간: 일반 24시간 이내, 긴급 1시간 이내

### 기술 지표

- 크래시 없는 세션 99.5% 이상
- 텍스트 메시지 전송 P95 800ms 이내
- 채팅방 최신 메시지 표시 P95 1.5초 이내
- 이미지 업로드 실패율 2% 미만
- 중복 포인트 적립 및 잔액 불일치 0건
- 월간 인프라 비용을 활성 사용자당 목표 예산 이내로 유지

## 3. 실행 원칙

1. 모바일 단일 코드베이스를 우선해 Android/iOS 기능 차이를 줄인다.
2. 인증, 채팅, 포인트, 권한은 서버를 단일 진실 공급원으로 둔다.
3. MVP에서 직접적인 사용자 가치가 없는 고급 기능은 후속 단계로 미룬다.
4. 개인정보, 성인 영역, 신고 정책은 개발 완료 후가 아니라 설계 단계에서 검토한다.
5. 성능과 비용은 이미지, 실시간 연결, 목록 조회를 중심으로 계측한다.
6. 모든 단계는 구현 완료가 아니라 수용 기준 통과로 종료한다.

## 4. 권장 기술 방향

구체 기술은 팀 역량과 운영 환경에 따라 확정하되 다음 원칙을 권장한다.

- 앱: Flutter 또는 React Native 기반 단일 코드베이스
- API: REST 중심, 채팅 전달에는 WebSocket 사용
- 데이터베이스: 트랜잭션과 권한 모델에 적합한 PostgreSQL
- 캐시/실시간 보조: 초기에는 관리형 서비스 또는 최소 Redis 구성
- 이미지: 객체 스토리지 + CDN, 업로드 전 클라이언트 압축
- 푸시: FCM/APNs 통합
- 인증: 국내 본인인증 제공자의 휴대전화 인증 결과 연동
- 관측성: 오류 수집, 핵심 API 지연, 크래시, 최소 제품 이벤트

초기 사용량이 작을 때는 관리형 모놀리식 API로 시작하고, 채팅/포인트/신고를 논리적 모듈로 분리한다. 운영 복잡도가 큰 마이크로서비스는 트래픽 근거가 생기기 전까지 도입하지 않는다.

## 5. 단계별 계획

### Phase 0. 제품 결정과 위험 제거

목표: 개발 전에 비용, 법률, 앱스토어 심사 위험을 확정한다.

작업:

- 서비스명 `Mute` 상표/도메인/앱스토어 중복 조사
- 본인인증 및 성인인증 제공자 2곳 이상 비용/SDK/심사 비교
- 성인 영역의 Apple App Store/Google Play 배포 가능 범위 검토
- 개인정보처리방침, 이용약관, 커뮤니티 가이드라인 초안
- 신고 등급, 대응 시간, 계정 제재 정책 확정
- MVP 최대 방 인원, 보존 기간, 사용자당 생성/가입 한도 확정
- 광고 네트워크의 리워드 검증 방식과 예상 수익 검토
- 핵심 화면 와이어프레임과 디자인 토큰 확정

종료 기준:

- 인증 사업자와 예상 건당 비용이 승인됨
- 성인 콘텐츠 허용 범위가 문서화됨
- MVP 범위와 제외 범위가 승인됨
- 핵심 10개 화면의 사용자 플로우가 검토됨

### Phase 1. 기반 구축

목표: 양 플랫폼에서 빌드, 배포, 모니터링 가능한 골격을 만든다.

작업:

- 앱 프로젝트와 개발/스테이징/운영 환경 구성
- CI에서 정적 분석, 단위 테스트, Android/iOS 빌드 수행
- API 프로젝트, 데이터베이스 마이그레이션, 환경 비밀 관리
- 공통 오류 응답, 인증 미들웨어, 감사 로그 기반 구현
- 디자인 토큰: 색상, 타이포그래피, 간격, 모서리, 그림자 정의
- 분석/크래시 이벤트의 개인정보 필터 설정

종료 기준:

- Android/iOS 스테이징 빌드 설치 가능
- 서버 헬스 체크와 마이그레이션 자동 실행
- 비밀 값이 저장소와 앱 번들에 포함되지 않음
- 오류 및 크래시가 스테이징 대시보드에 수집됨

### Phase 2. 인증과 계정

목표: 전화번호 본인인증을 통한 저비용 비밀번호 없는 로그인을 완성한다.

작업:

- 스플래시와 약관 동의
- 본인인증 SDK/웹 플로우 연동 및 서버 결과 검증
- 신규 가입/기존 계정 로그인 분기
- 세션 갱신, 안전한 토큰 저장, 로그아웃
- 인증 전화번호 마스킹 표시와 탈퇴
- 인증 재시도, 만료, 제한, 네트워크 오류 처리
- 기기/IP/전화번호 단위 인증 요청 제한

종료 기준:

- 신규/재로그인/로그아웃/탈퇴 E2E 테스트 통과
- 클라이언트가 위조한 인증 성공 값을 서버가 거부함
- 동일 전화번호로 중복 계정이 생성되지 않음
- 비밀번호 저장 및 비밀번호 찾기 기능이 존재하지 않음

### Phase 3. 방, 프로필 및 가입 승인

목표: 방 생성부터 가입 승인까지의 닫힌 루프를 완성한다.

작업:

- 방 생성/설명/편집/삭제 대기
- 방별 프로필 생성/변경
- 가입 신청, 대기 상태, 승인/거절
- 멤버 목록과 방별 프로필 상세
- 최대 멤버 수 동시성 검증
- 방장 양도
- 카테고리/지역/성인 여부 모델
- 제목/설명/해시태그 금칙어 및 길이 검증

종료 기준:

- 비멤버가 채팅 데이터에 접근할 수 없음
- 동시 승인 상황에서도 최대 멤버 수를 넘지 않음
- 방장 양도와 방 삭제 권한이 API에서 강제됨
- 방마다 다른 프로필이 서로 섞이지 않음

### Phase 4. 채팅과 이미지

목표: 텍스트와 이미지 대화를 안정적이고 낮은 비용으로 제공한다.

작업:

- WebSocket 연결, 재연결, 인증, 방 구독
- 텍스트 메시지 저장/수신/커서 페이지네이션
- 클라이언트 요청 ID 기반 중복 방지
- 전송 중/성공/실패 및 재전송 UI
- 카메라/갤러리 선택과 기본 크롭
- 클라이언트 리사이즈/압축/메타데이터 제거
- 서명 업로드 URL, 서버 MIME 검증, 썸네일 생성
- 시스템 메시지
- 방별/전체 알림과 푸시 토큰 관리

종료 기준:

- 재연결 후 메시지 누락/중복 없이 동기화됨
- 2,048px 초과 이미지가 정책 크기로 축소됨
- 목록 화면에서 원본 이미지 다운로드가 발생하지 않음
- 백그라운드 앱은 지속 연결 대신 푸시를 받음
- 성능 목표를 스테이징 부하 테스트에서 충족함

### Phase 5. 권한과 운영 기능

목표: 방장이 운영을 분담하되 권한 오용을 방지한다.

작업:

- 세부 권한 부여/회수 UI와 서버 권한 검사
- 가입 승인 권한
- 강퇴 5분/1시간/1일/30일
- 채팅 금지 5초/30초/1분/30분
- 타 멤버 이름 변경
- 스토리 관리 권한 데이터 모델
- 방 제목/대표 이미지/최대 멤버 수 수정 권한
- 운영 행위 감사 로그와 대상 알림

종료 기준:

- 권한별 허용/거부 통합 테스트 통과
- 운영자가 방장 또는 상위 역할을 제재할 수 없음
- 제재가 앱 재설치와 기기 변경 후에도 유지됨
- 모든 운영 행위의 행위자/대상/시각을 조회할 수 있음

### Phase 6. 탐색, 검색 및 노출

목표: 사용자가 적합한 방을 찾고 가입할 수 있게 한다.

작업:

- 프로모션/Member/지역별/성인 탭
- 방 제목/설명/해시태그 통합 검색
- 지역, 카테고리, 가입 가능 필터
- 무료 프로모션 쿨다운 및 종료 처리
- 활성 점수 시간 버킷 집계
- 도배 방지용 발신자 다양성/기여 상한
- 프로모션/활성 배지
- 신고 검토 상태에 따른 노출 제한

권장 MVP 활성화 규칙:

- 최근 30분 내 서로 다른 발신자 3명 이상
- 유효 텍스트/이미지 메시지 10개 이상
- 사용자 한 명의 점수 기여는 전체의 30% 이하
- 시스템 메시지, 삭제 메시지, 동일 내용 반복은 제외
- 점수는 시간 경과에 따라 감소

종료 기준:

- 세 검색 필드가 모두 검색 결과에 반영됨
- 무료 프로모션은 방별 24시간에 한 번만 가능함
- 프로모션과 자연 활성화가 UI 및 분석에서 구분됨
- 단일 계정 도배로 상위 노출이 불가능함
- 성인 미인증 사용자는 성인 방 데이터를 받지 않음

### Phase 7. 안전, 신고 및 성인인증

목표: 출시 전에 사용자 보호와 운영 대응 체계를 완성한다.

작업:

- 방/멤버/메시지 신고
- 신고 사유, 상세 입력, 증거 스냅샷, 접수 번호
- 사용자 차단과 메시지 접힘
- 긴급 신고 우선순위 큐
- 서비스 운영자 조치: 경고/숨김/정지/영구 정지/방 폐쇄
- 성인인증 연동과 성인 영역 데이터 차단
- 민감 콘텐츠 경고와 푸시 미리보기 제한
- 신고 데이터 보존/삭제 작업
- 운영 대응 런북과 비상 연락 체계

종료 기준:

- 신고자의 신원이 피신고자에게 노출되지 않음
- 긴급 신고가 지정된 대응 시간 안에 운영자에게 전달됨
- 미인증 계정으로 성인 API를 직접 호출해도 거부됨
- 정지 계정이 재로그인 후에도 서비스에 접근하지 못함
- 신고 처리자가 취한 모든 조치가 감사 로그에 남음

### Phase 8. 포인트, 광고 및 꾸미기

목표: 안전하고 검증 가능한 MVP 수익화 루프를 제공한다.

작업:

- 포인트 거래 원장과 잔액 조회
- 리워드 광고와 서버 검증 콜백
- 광고 일일 횟수/적립 한도
- 멤버 간 포인트 전송과 확인 화면
- 전송 일일/회당 한도, 이상 패턴 제한
- 기본/잠금 색상 팔레트
- 광고 또는 포인트로 색상/테마 잠금 해제
- 거래 이력과 고객 지원용 거래 ID

종료 기준:

- 광고 콜백 재전송에도 한 번만 적립됨
- 포인트 전송이 원자적으로 처리됨
- 음수 잔액이 발생하지 않음
- 결제 없이 기본 채팅 기능을 모두 사용할 수 있음
- 허용 색상 조합이 접근성 명암비를 충족함

### Phase 9. 베타와 출시

목표: 제한 사용자 환경에서 지표와 운영 준비를 검증하고 스토어에 출시한다.

작업:

- 내부 QA, 접근성 점검, 저사양 기기 테스트
- 핵심 사용자 플로우 E2E 자동화
- API 부하/장애/재연결/중복 요청 테스트
- 보안 점검과 권한 우회 테스트
- 50~200명 규모 비공개 베타
- 인증 비용, 이미지 저장/전송량, 실시간 연결 비용 계측
- 신고 운영 모의훈련
- 스토어 메타데이터, 개인정보 표시, 심사 계정 준비
- 점진 배포와 롤백 기준 설정

출시 게이트:

- Critical/High 결함 0건
- 핵심 E2E 100% 통과
- 크래시 없는 세션 99.5% 이상
- P95 성능 목표 달성
- 개인정보/약관/신고 문서 앱 내 접근 가능
- 운영 담당자와 긴급 신고 대응 채널 지정
- 비용 추정치가 승인된 월 예산 이내

## 6. 후속 로드맵

- 스토리 게시판 작성/편집/삭제
- 답장, 반응, 메시지 검색
- 신고 처리 결과 알림
- 방 운영 통계
- 추가 지역/관심사 필터

### Release 1.2

- 인앱 결제 포인트 패키지
- 광고 제거 구독
- 고급 테마와 프로필 장식
- 구매 복원과 환불 상태 동기화
- 이상 거래 탐지 고도화

### Release 2.0

- 음성 메시지와 짧은 영상
- 추천 개인화
- 선택형 커뮤니티 인증
- 운영자 웹 콘솔
- 자동 유해 콘텐츠 분류와 사용자 이의제기

## 7. 테스트 전략

### 단위 테스트

- 활성 점수 및 프로모션 쿨다운
- 권한 판정
- 제재 만료
- 이미지 크기/형식 정책
- 포인트 잔액 및 한도

### 통합 테스트

- 인증 결과 검증과 계정 중복 방지
- 가입 승인과 최대 멤버 수 동시성
- 메시지 중복 방지와 페이지네이션
- 포인트 전송 트랜잭션
- 광고 콜백 멱등성
- 신고 생성과 증거 보존

### E2E 테스트

- 설치 → 인증 → 메인 진입
- 방 검색 → 가입 신청 → 승인 → 첫 메시지
- 방 생성 → 운영 권한 부여 → 제재 → 만료
- 카메라/갤러리 → 크롭 → 이미지 전송
- 광고 시청 → 적립 → 멤버 전송 → 사용
- 성인 미인증/인증 계정의 접근 차이
- 신고 → 운영 조치 → 피신고 계정 제한

### 비기능 테스트

- 저사양 Android와 이전 지원 범위 iPhone 성능
- 불안정 네트워크, 오프라인, 앱 강제 종료 후 복구
- WebSocket 대량 연결과 메시지 팬아웃
- 이미지 폭탄, 잘못된 MIME, 비정상 파일
- API 권한 우회, 속도 제한, 세션 탈취 방어

## 8. 운영 준비

- 신고 큐 담당자와 교대/긴급 연락 규칙
- 인증 장애, 채팅 지연, 이미지 업로드 실패, 푸시 장애 런북
- 계정 정지/복구 승인 절차
- 개인정보 열람/삭제 요청 처리 절차
- 데이터베이스 백업과 복구 리허설
- 비용 알림: 인증, 객체 저장소, CDN, 실시간 연결, 푸시
- 주요 지표 대시보드와 장애 알림
- 앱 최소 지원 버전과 강제 업데이트 정책

## 9. 주요 위험과 완화책

| 위험 | 영향 | 완화책 |
|---|---|---|
| 인증 건당 비용 증가 | 가입 비용 상승 | 재전송 제한, 제공자 비교, 테스트 번호 분리 |
| 성인 영역 스토어 거절 | 출시 지연/기능 삭제 | Phase 0 사전 검토, 원격 기능 플래그, 별도 노출 차단 |
| 익명성 악용 | 신고 증가/브랜드 훼손 | 승인형 가입, 신고/차단, 계정 단위 제재, 감사 로그 |
| 메시지/이미지 비용 증가 | 마진 악화 | 압축, 썸네일, CDN, 보존 기간, 페이지네이션 |
| 도배로 활성 순위 조작 | 탐색 품질 저하 | 발신자 다양성, 기여 상한, 반복 메시지 제외 |
| 운영 권한 오용 | 멤버 이탈 | 세부 권한, 상위 역할 보호, 감사 기록, 방장 회수 |
| 포인트 중복 적립 | 직접 손실 | 서버 검증, 멱등 키, 원장, 일일 한도 |
| 신고 대응 인력 부족 | 안전 사고 | MVP 사용자 제한, 긴급 분류, 대응 시간과 인력 선확정 |

## 11. 즉시 필요한 입력

다음 항목은 구현 중 임의 결정하지 않고 제품 책임자의 승인을 받는다.

1. `Mute` 이름과 로고 방향의 최종 승인
2. Member 탭에서 허용할 역할 놀이의 정의와 연령 기준
3. MVP 성인 탭 포함 여부
4. 초기 지원 지역 목록
5. 최대 방 인원, 방 생성 수, 가입 방 수
6. 메시지와 이미지 보존 기간
7. 광고 1회당 포인트와 일일 광고 횟수
8. 포인트 전송 최소/최대 금액
9. 무료 프로모션 주기와 지속 시간
10. 신고 대응 담당자 및 운영 가능 시간
