# ORBIT 디자인 시스템

> 반익명 커뮤니티 채팅 앱을 위한 브랜드 및 UI 기준  
> 문서 상태: Working Draft v0.1  
> 브랜드명은 상표권, 앱스토어 중복, 도메인 검토 전의 가칭이다.

## 1. 브랜드 방향

### 1.1 제품 정의

ORBIT은 방마다 새로운 프로필로 참여하는 반익명 커뮤니티 채팅 서비스다. 익명성의 편안함은 유지하되, 방별 이름과 소개, 프로필 사진을 통해 관계의 맥락과 책임감을 만든다.

브랜드가 전달해야 할 인상은 다음과 같다.

- **밝고 공개적이다:** 어둡거나 폐쇄적인 익명 커뮤니티의 인상을 피한다.
- **성인에게도 자연스럽다:** 지나치게 귀엽거나 유행어 중심의 표현을 피한다.
- **가볍지만 가볍지 않다:** 빠른 채팅 경험과 신뢰 가능한 운영 도구를 함께 보여준다.
- **관계의 거리를 존중한다:** 실명 공개를 강요하지 않고, 각 방의 맥락에 맞는 정체성을 허용한다.
- **범용적이다:** 취미, 지역, 친목, 정보 교류 등 여러 커뮤니티에 적용할 수 있어야 한다.

### 1.2 브랜드 키워드

`연결` `궤도` `발견` `여백` `안심` `생동감`

### 1.3 보이스 원칙

- 짧고 명확한 존댓말을 사용한다.
- 사용자를 평가하거나 압박하지 않는다.
- 시스템 용어보다 사용자의 행동을 먼저 쓴다.
- 위험하거나 되돌리기 어려운 행동은 결과와 지속 시간을 명시한다.
- 익명성을 과장하지 않는다. 신고, 제재, 운영 정책이 적용됨을 투명하게 안내한다.

| 상황 | 권장 문구 | 피할 문구 |
| --- | --- | --- |
| 가입 신청 | `가입 신청을 보냈어요` | `신청 완료!!!` |
| 채팅 금지 | `30분 동안 채팅할 수 없어요` | `뮤트되었습니다` |
| 빈 채팅방 | `첫 메시지로 대화를 시작해 보세요` | `아직 아무도 없네요` |
| 오류 | `사진을 올리지 못했어요. 다시 시도해 주세요.` | `알 수 없는 오류가 발생했습니다` |
| 신고 | `신고 내용을 운영팀에서 검토합니다` | `신고가 접수되면 즉시 처벌됩니다` |

### 2.2 선정안: ORBIT / 오빗

**ORBIT**을 제품의 작업 브랜드로 선정한다.

선정 이유:

1. 사용자가 방마다 별도의 프로필을 갖는 구조를 `각 커뮤니티의 궤도에 들어간다`는 이야기로 자연스럽게 설명할 수 있다.
2. 원, 점, 궤도만으로 식별 가능한 로고와 모션을 만들 수 있어 작은 앱 아이콘에도 적합하다.
3. 특정 연령, 지역, 취미에 한정되지 않아 범용 SNS로 확장하기 쉽다.
4. 밝고 현대적인 영문 인상을 주면서 한국어로도 발음하기 쉽다.

권장 표기:

- 공식 영문명: `ORBIT`
- 공식 한국어명: `오빗`
- 서비스 설명형 표기: `오빗, 방마다 새로운 나`
- 영문 태그라인: `A different you in every circle.`
- 한국어 태그라인: `방마다 새로운 나`

출시 전 확인 항목:

- 한국 및 목표 국가의 상표 등록 가능성
- Apple App Store, Google Play 내 동종 앱 명칭
- `mute` 및 유사 철자 도메인과 SNS 핸들
- 금융, 암호화폐, 청소년 서비스 등 혼동 가능 업종

## 3. 로고 시스템

### 3.1 로고 콘셉트

기본 심볼은 **열린 궤도와 하나의 프로필 점**으로 구성한다.

- 바깥의 둥근 궤도는 채팅방과 커뮤니티를 의미한다.
- 궤도 위의 점은 방마다 달라지는 사용자의 프로필을 의미한다.
- 궤도의 작은 틈은 가입, 발견, 새로운 관계가 들어올 여백을 의미한다.
- 말풍선 꼬리를 직접 사용하지 않고도 채팅 서비스임을 느낄 수 있도록, 궤도 안쪽의 음영을 대화 공간처럼 처리한다.

### 3.2 형태 규칙

- 심볼은 정사각형 그리드 안에서 완전한 원을 기준으로 제작한다.
- 궤도 선 굵기는 전체 너비의 `10%`를 기준으로 한다.
- 프로필 점 지름은 전체 너비의 `22%`를 기준으로 한다.
- 궤도의 열린 각도는 약 `36deg`로 유지한다.
- 심볼 내부에 문자 `O`나 말풍선 꼬리를 중복해서 넣지 않는다.
- 최소 표시 크기는 디지털 기준 `20px`, 인쇄 기준 `6mm`다.
- 심볼 주변 최소 여백은 프로필 점 지름의 `1배`다.

### 3.3 로고 컬러

- 기본: `Mute Mint 600` 심볼 + `Ink 900` 워드마크
- 단색 밝은 배경: `Ink 900`
- 단색 어두운 배경: `White`
- 앱 아이콘: `Mute Mint 500` 배경 위 흰색 심볼
- 위험, 신고, 제재 컬러로 로고를 표현하지 않는다.

### 3.4 금지 사항

- 궤도를 타원으로 과도하게 찌그러뜨리지 않는다.
- 외곽선에 강한 네온이나 복수의 그림자를 적용하지 않는다.
- 로고 내부에 사진이나 복잡한 그라디언트를 넣지 않는다.
- 임의의 회전, 기울임, 자간 변경을 하지 않는다.
- 본문 문장 안에서는 워드마크 대신 텍스트 `오빗`을 사용한다.

## 4. 디자인 원칙

### 4.1 여백이 우선이다

정보를 선과 박스로 분리하기보다 여백, 타이포 위계, 배경 명도 차이로 구분한다. 한 화면의 강조 요소는 원칙적으로 하나만 둔다.

### 4.2 둥글지만 흐리지 않다

프로필, 태그, 카드, 버튼에는 일관된 라운딩을 적용한다. 모든 요소를 캡슐 형태로 만들지 않으며, 정보 구조가 모호해질 정도의 장식은 피한다.

### 4.3 뉴모피즘은 표면 표현에만 쓴다

그림자는 카드와 선택 가능한 표면의 깊이를 살짝 구분하는 용도로 사용한다. 입력창, 텍스트, 핵심 상태를 그림자만으로 구분하지 않는다. 경계선과 색 대비를 함께 사용한다.

### 4.4 채팅이 가장 빠른 경로다

이미 가입한 방은 방 상세에서 한 번의 행동으로 채팅에 진입한다. 자주 쓰는 채팅, 사진, 알림 기능은 화면 깊이 1단계 안에 둔다.

### 4.5 신뢰가 장식보다 우선이다

성인 인증, 가입 승인, 결제, 신고, 권한 부여는 상태와 결과를 명확히 보여준다. 광고 시청과 포인트 사용은 실행 전에 비용과 보상을 숫자로 표시한다.

### 5.3 사용 규칙

- 초록색은 주요 행동, 선택, 활성 상태, 포인트 보상에 사용한다.
- 핑크 레드는 신고, 삭제, 강퇴, 결제 오류 등 높은 주의가 필요한 상태에만 사용한다.
- 프로모션 방과 활발한 방은 색뿐 아니라 `프로모션`, `지금 활발해요` 라벨로 구분한다.
- 한 화면에서 채도가 높은 초록색 면적은 전체의 약 `10%` 이내로 유지한다.
- 사용자 지정 채팅 색은 최소 명암비를 통과한 프리셋을 기본 제공한다.
- 다크 모드는 초기 출시 범위에서 제외할 수 있으나 토큰 구조는 테마 확장이 가능해야 한다.

## 6. 타이포그래피

### 6.1 서체

- 한국어 및 공통 UI: `Pretendard Variable`
- Android 대체: `Noto Sans KR`, `sans-serif`
- iOS 대체: `Apple SD Gothic Neo`, system font
- 숫자, 포인트, 시간은 본문과 같은 서체의 `tabular-nums` 기능을 사용한다.
- 로고 워드마크 외에 별도 장식 서체를 사용하지 않는다.

### 6.2 타입 스케일

| 토큰 | 크기 / 행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| `display-sm` | `28 / 38` | 700 | 온보딩 핵심 문구 |
| `heading-lg` | `24 / 34` | 700 | 화면 제목 |
| `heading-md` | `20 / 30` | 700 | 섹션 제목, 방 이름 |
| `heading-sm` | `18 / 27` | 600 | 카드 제목 |

| `body-sm` | `13 / 20` | 400 | 설명, 메타 정보 |

### 6.3 타이포 규칙

- 채팅 본문은 사용자가 선택 가능한 `15px`, `17px`, `19px` 세 단계를 제공한다.
- 본문 줄 길이는 모바일 기준 한 줄에 한글 약 `18~26자`를 권장한다.
- 제목은 최대 2줄, 목록의 방 설명은 최대 2줄에서 말줄임한다.
- 숫자와 단위를 분리하지 않는다. 예: `30분`, `1,200P`.
- 영문 대문자만으로 긴 문장을 쓰지 않는다.
- 텍스트만으로 계층을 표현할 때 최소 두 단계 이상의 크기 또는 굵기 차이를 둔다.

## 7. 레이아웃과 간격

### 7.1 기본 그리드

- 기준 단위는 `4dp`다.
- 모바일 화면 좌우 안전 여백은 기본 `20dp`, 좁은 화면은 최소 `16dp`다.
- 태블릿 콘텐츠 최대 너비는 `720dp`로 제한하고 중앙 정렬한다.
- 하단 내비게이션과 입력 영역은 기기 Safe Area를 포함한다.

| `space-16` | `64` | 빈 상태의 큰 간격 |

### 7.3 터치 영역

- 모든 터치 대상은 최소 `44 x 44pt` 또는 `48 x 48dp`를 확보한다.
- 인접한 작은 아이콘 버튼 사이에는 최소 `8dp` 간격을 둔다.
- 목록 행의 기본 높이는 `64dp`, 프로필을 포함한 방 목록은 `80~88dp`다.

## 8. 라운딩

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `radius-xs` | `6` | 작은 상태 배지 |
| `radius-sm` | `10` | 태그, 작은 입력 |
| `radius-md` | `14` | 버튼, 일반 입력 |
| `radius-lg` | `18` | 카드, 채팅 풍선 |
| `radius-xl` | `24` | 바텀 시트, 큰 카드 |
| `radius-full` | `999` | 프로필, 토글, 캡슐 |

규칙:

- 프로필 사진은 항상 원형이다. 방 대표 이미지는 `radius-lg` 사각형을 사용한다.
- 버튼과 입력창은 같은 높이에서 같은 `radius-md`를 사용한다.
- 채팅 풍선은 기본 `radius-lg`이며 화자 방향의 아래 모서리 하나만 `6dp`로 줄인다.
- 중첩된 표면은 바깥 요소보다 안쪽 요소의 반경을 작게 한다.

## 9. 깊이와 그림자

### 9.1 절제된 뉴모피즘

뉴모피즘은 흰색 표면이 배경에서 아주 조금 떠 있는 느낌만 제공한다. 사용 가능 여부나 선택 상태를 그림자에만 의존하지 않는다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `shadow-xs` | `0 1px 2px rgba(18,26,22,.05)` | 태그, 얇은 구분 |
| `shadow-sm` | `0 2px 8px rgba(18,26,22,.07), 0 -1px 2px rgba(255,255,255,.8)` | 입력, 작은 카드 |
| `shadow-md` | `0 6px 18px rgba(18,26,22,.09), 0 -2px 5px rgba(255,255,255,.9)` | 방 카드, 플로팅 버튼 |
| `shadow-lg` | `0 16px 40px rgba(18,26,22,.14)` | 모달, 바텀 시트 |
| `shadow-inset` | `inset 0 1px 3px rgba(18,26,22,.08)` | 눌림 상태에 제한 사용 |

### 9.2 그림자 규칙

- 기본 카드에는 `1px` 경계선과 `shadow-sm`을 함께 사용한다.
- 스크롤 목록의 모든 행에 그림자를 주지 않는다. 그룹 카드 또는 선택 항목에만 사용한다.
- 누른 상태는 그림자를 줄이고 배경 명도를 낮춘다.
- 비활성 요소는 그림자를 제거하고 대비를 낮춘다.
- 채팅 풍선에는 그림자를 사용하지 않거나 `shadow-xs`까지만 허용한다.
- 그림자 색에 순수 검정이나 브랜드 초록을 사용하지 않는다.

## 10. 아이콘과 이미지

### 10.1 아이콘

- 둥근 끝을 가진 `2px` 선형 아이콘을 기본으로 한다.
- 기본 크기는 `24dp`, 보조 아이콘은 `20dp`, 상태 아이콘은 `16dp`다.
- 주요 탭의 선택 상태는 채움 아이콘과 텍스트 색을 함께 바꾼다.
- 의미가 불명확한 아이콘에는 반드시 라벨이나 접근성 이름을 제공한다.
- 신고, 강퇴, 삭제 아이콘은 서로 구분되는 형태와 문구를 사용한다.

### 10.2 프로필과 방 이미지

- 사용자 프로필: 목록 `40dp`, 채팅 `36dp`, 프로필 상세 `88dp`.
- 방 대표 이미지: 목록 `56 x 56dp`, 상세 상단은 화면 너비 기준 `16:9`.
- 이미지가 없을 때는 이름 첫 글자와 중립 또는 사전 정의된 색 조합을 사용한다.
- 업로드 전 사용자가 `1:1` 프로필 크롭 또는 `16:9` 방 이미지 크롭을 선택하게 한다.
- 흐린 원본을 과도하게 확대하지 않으며, 실패 시 텍스트 기반 대체 이미지를 보여준다.
- 사진 위 텍스트는 반투명 오버레이를 포함해 `4.5:1` 이상의 대비를 확보한다.

## 11. 핵심 컴포넌트

### 11.1 버튼

#### Primary

- 화면의 대표 행동 하나에 사용한다.
- 높이 `52dp`, 좌우 패딩 `20dp`, `radius-md`.
- 배경 `color-action-primary`, 텍스트 `white`.
- 로딩 중에는 너비를 유지하고 인디케이터와 동작 문구를 표시한다.

#### Secondary

- 흰색 표면, `color-border-default` 경계, `color-text-primary` 텍스트.
- Primary와 동일한 크기 체계를 사용한다.

#### Tertiary

- 배경 없는 텍스트 또는 아이콘 버튼.
- 목록의 보조 행동과 툴바에 사용한다.

#### Danger

- 삭제, 강퇴, 신고 확정에만 사용한다.
- 위험도가 낮은 진입 버튼은 중립색으로 두고 최종 확인 버튼만 핑크 레드를 사용한다.

#### 상태

- Disabled: 배경 `gray-200`, 텍스트 `gray-500`.
- Pressed: 배경을 한 단계 어둡게 하고 그림자를 줄인다.
- Focus: 외곽 `2px color-focus`와 `2px` 여백.
- Loading: 중복 탭을 막되 취소 가능한 업로드는 취소 수단을 제공한다.

### 11.2 입력창

- 기본 높이 `52dp`, 여러 줄 입력은 최소 `96dp`.
- 항상 보이는 라벨을 입력창 위에 둔다. placeholder를 라벨로 사용하지 않는다.
- 오류는 테두리, 아이콘, 문구를 함께 사용한다.
- 글자 수 제한은 제한의 `80%`부터 표시한다.
- 전화번호는 국가 코드와 번호를 분리하고 읽기 쉬운 형식으로 표시한다.

### 11.3 검색

- 상단 검색창은 `검색어 또는 해시태그` placeholder를 사용한다.
- 방 제목, 설명, 해시태그를 한 번에 검색하며 결과에서 일치한 부분을 강조한다.
- 최근 검색어는 기기에서 삭제할 수 있어야 한다.
- 검색 결과에서 가입 상태를 `참여 중`, `승인 대기`, `가입 신청`으로 바로 구분한다.

### 11.4 태그와 칩

- Notion과 유사하게 낮은 채도의 배경색과 진한 텍스트를 사용한다.
- 태그 높이는 `28dp`, 좌우 패딩 `10dp`, 간격 `6dp`.
- 해시태그 텍스트 앞에는 `#`을 표시한다.
- 지역, 성인, 프로모션, 활동 상태는 해시태그와 다른 의미 기반 아이콘 또는 라벨을 함께 쓴다.
- 한 카드에는 최대 3개를 노출하고 나머지는 `+4`처럼 접는다.

### 11.5 방 카드

필수 정보:

- 방 대표 이미지
- 방 이름
- 1~2줄 방 설명
- 주요 해시태그 최대 3개
- 현재 멤버 수와 최대 멤버 수
- 가입 상태
- `프로모션` 또는 `지금 활발해요` 상태

규칙:

- 카드 전체를 탭할 수 있게 하고 내부 행동은 하나 이하로 제한한다.
- 프로모션은 브랜드 배지, 활성 방은 움직임 없는 상태 점과 문구로 구분한다.
- 활발함을 과장하는 지속 애니메이션은 사용하지 않는다.
- 이미 참여 중인 방은 `채팅으로`를 대표 행동으로 표시한다.

### 11.6 채팅 풍선

- 내 채팅은 오른쪽, 다른 사람의 채팅은 왼쪽에 정렬한다.
- 내 기본 풍선은 `green-100`, 상대 풍선은 `white`와 `color-border-default`를 사용한다.
- 연속 메시지는 같은 사람 기준 2분 이내일 때 프로필과 이름을 생략할 수 있다.
- 시간과 전송 상태는 풍선 바깥에 배치해 본문 공간을 확보한다.
- 사용자 지정 풍선/텍스트 색은 접근성 검증을 통과한 조합만 저장한다.
- 사진은 썸네일을 먼저 표시하고 원본은 명시적으로 열 때 불러온다.
- 신고 및 답장 메뉴는 길게 누르기와 접근 가능한 별도 메뉴 버튼을 모두 제공한다.

### 11.7 프로필 목록

- 원형 사진, 방 전용 이름, 한 줄 소개, 역할 배지를 표시한다.
- 방장과 운영 권한은 색만이 아닌 텍스트 배지로 표시한다.
- 포인트 보내기, 신고, 권한 관련 행동은 프로필 상세 또는 더보기 메뉴에 둔다.
- 이름 변경 권한 사용 시 변경 주체와 적용 범위를 확인 문구로 보여준다.

### 11.8 바텀 시트와 다이얼로그

- 선택지가 3개 이상이거나 추가 설명이 필요하면 바텀 시트를 사용한다.
- 즉시 판단이 필요한 확인과 오류에는 다이얼로그를 사용한다.
- 강퇴 및 채팅 금지 시간은 라디오 목록으로 명시한다.
- 방 삭제, 방장 이전은 대상과 결과를 다시 적고 최종 확인을 요구한다.
- 취소 버튼은 항상 제공하며 위험 행동을 기본 포커스로 두지 않는다.

### 11.9 토스트, 배너, 상태

- 토스트는 되돌릴 필요 없는 짧은 성공 안내에만 사용한다.
- 가입 승인 대기, 네트워크 끊김처럼 지속되는 상태는 배너로 표시한다.
- `방금`, `3분 전` 같은 상대 시간에는 접근성 레이블로 정확한 날짜와 시간을 제공한다.

### 11.10 광고, 결제, 포인트

- 광고 시청 전 `광고를 보고 30P 받기`처럼 보상과 조건을 표시한다.
- 유료 테마와 광고 해제는 가격, 적용 범위, 복원 가능 여부를 함께 표시한다.
- 포인트 보내기는 받는 사람, 금액, 잔액을 확정 화면에 표시한다.
- 광고와 일반 콘텐츠 사이에는 `광고` 라벨과 시각적 구획을 둔다.
- 결제 버튼 근처에 오해를 유도하는 카운트다운이나 위장 닫기 버튼을 사용하지 않는다.

## 12. 내비게이션

### 12.1 메인 구조

하단 내비게이션은 핵심 목적을 기준으로 최대 4개를 권장한다.

1. `둘러보기`: 프로모션, Member, 지역별, 성인 하위 탭
2. `내 채팅`: 참여 중인 방과 승인 대기 상태
3. `알림`: 가입 신청, 승인, 운영 알림, 멘션
4. `내 정보`: 계정, 인증 전화번호, 알림, 정책, 피드백

메인 `둘러보기`의 상단 카테고리는 가로 스크롤 탭으로 제공한다.

- `추천`: 프로모션 방과 활발한 방을 명확한 라벨로 혼합 노출
- `Member`: 멤버 놀이 목적의 방
- `지역별`: 선택 지역 필터 포함
- `성인`: 성인 인증 완료 후 진입

`프로모션`은 사용자에게 광고성 목록으로만 인식될 수 있으므로, 메인 탭 이름은 `추천`을 우선 검토한다. 목록 안에서 프로모션과 자연 활성화 상태를 반드시 구분한다.

### 12.2 뒤로 가기

- Android 시스템 뒤로 가기와 화면 상단 뒤로 가기는 동일하게 동작한다.
- 작성 중인 스토리, 방 편집, 긴 소개는 이탈 전 저장 여부를 확인한다.
- 닫기와 뒤로 가기의 의미를 혼용하지 않는다.

## 13. 핵심 화면 UI 원칙

### 13.1 스플래시와 가입

- 스플래시는 로고와 단색 배경만 사용하고 앱 초기화가 끝나는 즉시 종료한다.
- 전화번호 인증의 목적과 사용 범위를 인증 전에 안내한다.
- 인증번호 자동 입력을 지원하고 남은 시간과 재전송 가능 시점을 표시한다.
- 저비용 비밀번호 복구는 전화번호 OTP 재인증을 기본으로 한다.
- 계정 존재 여부를 과도하게 노출하지 않는 오류 문구를 사용한다.

### 13.2 방 탐색과 검색

- 상단에 검색, 그 아래 카테고리 탭, 본문에 방 목록을 둔다.
- 프로모션과 활발한 방의 순위 이유를 라벨로 설명한다.
- 지역과 성인 여부는 필터로 다시 확인할 수 있게 한다.
- 무한 스크롤 시 스켈레톤을 최소 사용하고 이전 콘텐츠를 유지한다.
- 빈 검색 결과에는 필터 해제와 검색어 수정 행동을 제공한다.

### 13.3 방 상세

- 대표 이미지, 방 이름, 설명, 태그, 멤버 수, 운영 상태 순으로 배치한다.
- 이미 가입한 사용자의 고정 하단 버튼은 `채팅으로`다.
- 미가입 사용자의 고정 하단 버튼은 `가입 신청`이다.
- 신청 대기 상태는 버튼을 비활성화하는 대신 `승인 대기 중`과 신청 취소 행동을 제공한다.
- 방 신고는 더보기 메뉴에 두되 쉽게 발견할 수 있어야 한다.

### 13.4 채팅방

- 상단에는 방 이름, 현재 멤버 또는 활동 상태, 알림 토글 진입점을 둔다.
- 메시지 목록, 새 메시지 표시, 입력창이 시각적 우선순위의 대부분을 차지한다.
- 입력창에는 텍스트, 사진, 전송만 기본 노출하고 나머지는 확장 메뉴에 둔다.
- 스토리, 멤버 목록, 방 정보는 상단의 명확한 진입점으로 제공한다.
- 새 메시지가 도착해도 사용자가 과거 메시지를 읽는 중이면 위치를 강제로 이동하지 않는다.
- 채팅 금지 상태에서는 남은 시간과 사유를 입력창 위치에 표시한다.

### 13.5 스토리

- 방 단위 게시판임을 화면 제목과 방 이름으로 명확히 한다.
- 목록은 제목, 작성자 방 프로필, 작성 시간, 대표 이미지, 반응 수를 보여준다.
- 작성 권한이 없는 사용자는 작성 버튼을 숨기고 권한 안내를 설정 화면에서 확인하게 한다.
- 편집 이력이나 운영자 수정 여부를 게시물에 표시한다.

### 13.6 멤버와 권한 관리

- 방장, 부방장, 일반 멤버를 텍스트 태그로 구분한다.
- 부방장은 복수 지정할 수 있으며 단일 역할 토글로 설정한다.
- 강퇴와 채팅 금지는 기간을 먼저 선택하고 대상과 결과를 확인한다.
- 방장 이전은 새 방장 선택, 권한 변화 안내, 최종 인증의 3단계로 구성한다.
- 자기 자신 또는 현재 방장에게 적용할 수 없는 역할 변경은 이유와 함께 비활성화한다.

### 13.7 방 생성과 편집

- 생성 흐름은 `기본 정보 → 공개 및 가입 방식 → 지역/성인/태그 → 확인`으로 나눈다.
- 최대 멤버 수 변경이 운영 비용 또는 정책에 영향을 주면 즉시 설명한다.
- 방 삭제는 일반 편집 화면과 시각적으로 분리된 위험 영역에 둔다.
- 프로모션 실행 시 노출 방식, 재실행 조건, 종료 시점을 표시한다.

### 13.8 설정

- 계정: 인증된 전화번호, 로그아웃, 계정 삭제
- 알림: 전체 알림, 채팅, 가입 및 운영, 마케팅
- 이용 안내: 개인정보 처리방침, 이용약관, 커뮤니티 가이드
- 지원: 이메일 피드백, 앱 버전, 오픈소스 라이선스
- 인증 전화번호는 일부를 마스킹하되 사용자가 본인 번호를 식별할 수 있게 한다.
- 전체 알림을 끄면 하위 토글 상태는 보존하고 비활성화한다.

## 14. 접근성

### 14.1 대비와 색

- 일반 텍스트는 WCAG AA 기준 `4.5:1` 이상을 확보한다.
- 18pt 이상 또는 14pt Bold 이상의 큰 텍스트는 `3:1` 이상을 확보한다.
- 아이콘, 입력 테두리, 포커스 표시 같은 UI 요소는 인접 색과 `3:1` 이상을 확보한다.
- 상태와 역할은 색만으로 표현하지 않고 텍스트, 아이콘, 형태를 함께 사용한다.
- 사용자 지정 테마도 같은 대비 기준을 통과해야 활성화할 수 있다.

### 14.2 스크린 리더

- 프로필 이미지는 `민지의 프로필 사진`, 방 이미지는 `서울 러닝 모임 대표 이미지`처럼 맥락을 제공한다.
- 장식 이미지는 접근성 트리에서 제외한다.
- 채팅은 `보낸 사람, 메시지, 시간, 전송 상태` 순으로 읽는다.
- 새 메시지 도착을 매번 강제 낭독하지 않고 사용자가 알림 수준을 선택할 수 있게 한다.
- 아이콘 버튼은 보이는 툴팁과 접근성 이름을 제공한다.

### 14.3 동작과 입력

- OS 글자 크기 `200%`까지 핵심 정보와 행동이 잘리지 않아야 한다.
- 모션 감소 설정 시 궤도 회전, 카드 이동, 숫자 애니메이션을 제거한다.
- 화면 전환은 기본 `180~240ms`, 강조 모션은 최대 `320ms`로 제한한다.
- 진동 피드백은 전송, 오류, 위험 확정처럼 의미 있는 순간에만 사용하며 끌 수 있게 한다.
- 키보드가 올라와도 채팅 입력과 전송 버튼이 가려지지 않아야 한다.

### 14.4 콘텐츠 안전

- 신고 메뉴는 프로필, 메시지, 스토리, 방에서 일관된 위치와 명칭을 사용한다.
- 신고 후 차단 선택지를 제공하되 두 행동의 차이를 설명한다.
- 민감한 이미지에는 사용자가 열기 전 경고 또는 블러 처리를 적용할 수 있다.
- 성인 탭은 성인 인증 상태와 콘텐츠 표시 설정을 함께 확인한다.

## 15. 모션

- 모션은 상태 변화의 원인을 설명하는 데만 사용한다.
- 기본 이징: `cubic-bezier(0.2, 0, 0, 1)`.
- 탭 및 버튼 피드백: `100~140ms`.
- 화면 및 시트 전환: `180~240ms`.
- 앱 시작 시 로고 궤도는 1회 이하의 미세한 움직임만 허용한다.
- 방 목록 순위가 바뀌어도 항목을 과도하게 튀기거나 자동 스크롤하지 않는다.
- 전송 성공 애니메이션은 반복하지 않고 메시지 상태 아이콘으로 마무리한다.

## 16. 반응형과 플랫폼

- 공통 디자인 토큰과 정보 구조를 유지하되 iOS와 Android의 네이티브 탐색 관습을 따른다.
- iOS는 스와이프 뒤로 가기, Action Sheet, Dynamic Type을 지원한다.
- Android는 시스템 뒤로 가기, Material 형식의 권한 요청, 예측 뒤로 가기를 지원한다.
- 플랫폼별 상태 바, Safe Area, 키보드 높이를 하드코딩하지 않는다.
- 태블릿에서는 방 목록과 채팅을 2열로 구성할 수 있으나 모바일의 단일 열 흐름을 우선 완성한다.

## 17. 성능을 위한 UI 규칙

- 방 목록과 채팅 목록은 가상화하고 화면에 보이는 항목만 렌더링한다.
- 목록 썸네일은 표시 크기의 약 2배 해상도로 생성하며 원본을 직접 내려받지 않는다.
- 사진 업로드는 크롭 후 긴 변 기준 최대 `2048px`, 품질 `75~85%`의 WebP 또는 플랫폼 적합 포맷을 우선한다.
- 채팅 사진은 저용량 썸네일을 먼저 표시하고 상세 진입 시 고해상도 이미지를 불러온다.
- 스켈레톤, 블러, 그림자를 중첩해 GPU 비용을 높이지 않는다.
- 실시간 활동 상태는 매 메시지마다 전체 목록을 갱신하지 않고 서버에서 계산된 묶음 지표를 사용한다.
- 테마는 이미지보다 컬러와 토큰 기반으로 구성해 다운로드 크기와 렌더링 비용을 줄인다.

## 18. 디자인 QA 체크리스트

### 화면 공통

- 대표 행동이 하나로 명확한가?
- 터치 영역이 최소 기준을 충족하는가?
- 텍스트 확대 시 잘림이나 겹침이 없는가?
- 색 없이도 상태를 구분할 수 있는가?
- 로딩, 빈 상태, 오류, 오프라인 상태가 정의되어 있는가?
- 키보드와 Safe Area가 주요 행동을 가리지 않는가?

### 채팅

- 내 메시지와 상대 메시지가 색 외의 정렬로도 구분되는가?
- 긴 이름, 긴 메시지, 연속 사진, 전송 실패를 처리하는가?
- 과거 메시지를 읽는 사용자의 위치를 보존하는가?
- 신고와 차단 경로가 접근 가능한가?

### 운영과 결제

- 권한의 대상, 기간, 결과가 확정 전에 보이는가?
- 위험 행동에 취소와 재확인이 있는가?
- 광고 보상과 결제 가격이 행동 전에 보이는가?
- 포인트 잔액과 거래 결과가 명확한가?

## 19. 토큰 명명 및 구현 원칙

- 제품 코드에서는 원시 색 이름보다 의미 기반 토큰을 우선 사용한다.
- 컴포넌트 토큰은 `component-state-property` 순으로 명명한다.
- 예: `button-primary-bg`, `button-primary-bg-pressed`, `chat-bubble-mine-bg`.
- 플랫폼별 값이 달라도 동일한 의미 토큰 이름을 유지한다.
- 임의의 색, 간격, 그림자를 화면 코드에 직접 추가하지 않는다.
- 새 토큰은 두 화면 이상에서 반복되거나 독립된 의미가 있을 때만 추가한다.

## 20. 초기 출시 우선순위

첫 출시에서는 다음 범위를 디자인 시스템의 필수 구현 대상으로 삼는다.

1. 스플래시, 전화번호 인증, 계정 복구
2. 방 탐색, 검색, 필터, 방 상세, 가입 신청
3. 채팅, 사진 전송, 방 전용 프로필, 알림
4. 스토리 목록 및 작성
5. 방 생성, 편집, 가입 승인, 멤버 및 권한 관리
6. 신고, 차단, 성인 인증
7. 포인트 보내기, 광고 보상, 유료 테마
8. 설정, 정책, 피드백

브랜드와 디자인 시스템은 익명성을 시각적 은폐로 표현하지 않는다. ORBIT의 핵심은 숨는 경험이 아니라, 각 커뮤니티에서 필요한 만큼의 나를 선택하고 편안하게 연결되는 경험이다.
